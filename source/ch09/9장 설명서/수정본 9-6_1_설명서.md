# 9-6_1.py 프로그램 설명서 — 웹캠 의미 분할 및 동영상 저장

- **기준 소스:** `9-6_1.py` (첨부된 수정본)
- **교재 연결:** 9장 프로그램 9-6(웹캠 의미 분할, 412쪽 부근)
- **최신 보충 내용:** 원본 PixelLib를 **Hugging Face SegFormer + PyTorch**로 대체했습니다.

## 1. 선수 지식 확인

9-5_1의 픽셀별 의미 분할, OpenCV 영상 캡처의 `ret, frame`, `while` 반복문을 이해하고 시작합니다.

## 2. 오늘의 학습 목표

1. 정지 영상의 의미 분할을 웹캠의 연속 프레임에 적용합니다.
2. CPU/GPU 중 사용할 장치를 선택합니다.
3. 결과를 화면에 표시하고 `output_video.mp4`로 저장합니다.

## 3. 핵심 개념과 처리 흐름

**비유:** 사진 한 장을 색칠하는 9-5_1을 빠르게 반복하는 것이 이 프로그램입니다. 카메라 영상은 사진이 초당 여러 장 이어진 형태입니다.

```text
웹캠 연결 → 한 프레임 읽기(BGR)
         → RGB 변환 → SegFormer 추론
         → 원본 크기로 마스크 확대
         → 60% 원본 + 40% 색 마스크
         → 화면 출력 + mp4 파일 기록
         → 다음 프레임 ... → q 키 → 자원 해제
```

## 4. 단계별 핵심 코드

### ① 연산 장치 선택

```python
device = 'cuda' if torch.cuda.is_available() else 'cpu'
model = SegformerForSemanticSegmentation.from_pretrained(model_id).to(device)
```

`cuda`는 사용 가능한 NVIDIA GPU에서 PyTorch가 CUDA를 지원할 때 선택됩니다. 그렇지 않으면 CPU로 처리합니다. **TensorFlow에서 GPU를 사용하지 못하는 것과 PyTorch의 GPU 사용 가능 여부는 다를 수 있습니다.**

### ② 웹캠 시작

```python
cap = cv.VideoCapture(0)
if not cap.isOpened():
    raise RuntimeError('웹캠을 열 수 없습니다.')
```

`0`은 기본 카메라 번호입니다. 다른 프로그램이 카메라를 사용 중이면 연결이 실패할 수 있습니다.

### ③ 저장할 동영상 준비

```python
width = int(cap.get(cv.CAP_PROP_FRAME_WIDTH))
height = int(cap.get(cv.CAP_PROP_FRAME_HEIGHT))
fourcc = cv.VideoWriter_fourcc(*'mp4v')
fps = 5.0
out = cv.VideoWriter('output_video.mp4', fourcc, fps, (width, height))
```

`VideoWriter`는 영상 파일을 기록합니다. **`fps=5.0`은 저장 영상의 재생 속도 설정이지 AI가 실제 초당 5프레임을 처리한다는 뜻은 아닙니다.** 추론 속도가 느리면 녹화된 영상의 시간 흐름이 실제 시간과 달라질 수 있습니다.

### ④ 프레임별 추론과 후처리

```python
rgb_frame = cv.cvtColor(frame, cv.COLOR_BGR2RGB)
inputs = processor(images=rgb_frame, return_tensors='pt').to(device)
with torch.no_grad():
    outputs = model(**inputs)
```

카메라 영상(BGR)을 RGB로 변경하고 모델에 전달합니다. 추론을 위해 입력과 모델을 **같은 장치**에 두어야 합니다.

```python
upsampled_logits = F.interpolate(
    outputs.logits, size=(height, width),
    mode='bilinear', align_corners=False
)
predicted_mask = upsampled_logits.argmax(dim=1).squeeze().cpu().numpy()
```

픽셀마다 가장 높은 클래스 점수를 선택하고 원본 카메라 해상도로 되돌립니다.

### ⑤ 합성·저장·종료

```python
overlay_frame = cv.addWeighted(frame, 0.6, color_mask_bgr, 0.4, 0)
cv.imshow('Pixellib (SegFormer)', overlay_frame)
out.write(overlay_frame)
```

화면 창 이름에는 `Pixellib`가 남아 있지만, **실제로 PixelLib를 사용하는 코드는 아닙니다.** `q`를 누르면 루프가 종료되고 `cap.release()`, `out.release()`, `cv.destroyAllWindows()`로 장치를 닫습니다.

## 5. 간단한 실습

1. `pip install transformers torch numpy opencv-python`으로 준비합니다.
2. 웹캠이 다른 앱에서 사용 중인지 확인한 후 실행합니다.
3. 사람과 책상, 벽 등 여러 물체가 있는 장면에서 색 영역이 어떻게 변하는지 관찰합니다.
4. `q`로 종료한 뒤 실행 작업 폴더의 `output_video.mp4`를 열어 봅니다.

## 6. 오류·주의 사항

| 현상 | 확인할 원인 | 해결 순서 |
|---|---|---|
| 웹캠 실패 | 카메라 앱이 점유 중인지 확인 | 앱 종료 → 카메라 번호 변경 |
| 출력 파일 없음/재생 불가 | `out.isOpened()` 여부와 코덱 확인 | 저장 경로·mp4v 지원 확인 |
| 동작이 느림 | CPU 추론 시간이 김 | 입력 해상도 축소 또는 CUDA 지원 점검 |
| 영상 속도가 이상함 | 실제 처리 FPS와 저장 FPS 불일치 | 실제 처리 속도 측정 후 FPS 조정 |
| 파일 위치를 모름 | 상대 경로 사용 | `Path('output_video.mp4').resolve()` 출력 |


## 확인 문제 3개 (정답 대신 힌트)

1. `cv.VideoCapture(0)`의 숫자 0은 무엇일까요? **힌트:** 카메라 장치 번호입니다.
2. `out.write()`가 빠지면 어떤 결과가 발생할까요? **힌트:** 화면 출력과 파일 저장은 서로 다른 작업입니다.
3. `fps=5.0`이 실제 AI의 처리 속도를 보장할까요? **힌트:** 저장 정보와 계산 시간은 다릅니다.
