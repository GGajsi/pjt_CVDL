# 11-1 — CIFAR-10에서 직접 만드는 기본 ViT 분류기

> 주 교재: 『컴퓨터 비전과 딥러닝』 11장 **비전 트랜스포머**(PDF 481쪽부터), **11-5 비전 트랜스포머 프로그래밍 실습**(PDF 531쪽부터). 이 자료는 업로드된 `11-1.py`의 실제 코드에 근거합니다. 교재 페이지는 관련 개념·실습을 찾아보기 위한 위치입니다.

## 1. 선수 지식 확인

CIFAR-10의 이미지 크기(32×32×3), `Dense`, `softmax`, 훈련/테스트 데이터의 역할을 알고 있나요?

## 2. 오늘의 학습 목표

1. 이미지를 패치로 나누고 64개의 토큰을 만드는 이유를 설명한다.
2. 위치 임베딩과 다중 헤드 주목의 역할을 이해한다.
3. 모델 구성 오류를 찾아 올바른 6개 인코더 블록으로 수정할 수 있다.

## 3. 핵심 개념 — 일상 비유

한 장의 그림을 4×4 크기의 **퍼즐 64조각**으로 나누고, 각 퍼즐 조각이 다른 조각을 바라보며 전체 장면을 이해하는 것에 비유할 수 있습니다. 패치의 순서가 사라지지 않도록 위치표를 붙입니다.

## 4. 프로그램 처리 흐름

```text
CIFAR-10 32×32×3 → 4×4 패치 64개 → Dense(64) + 위치 임베딩
→ LayerNorm → MultiHeadAttention(8 heads) → 잔차 연결 → MLP
→ (의도상 6회 반복) → Flatten → Dense → Softmax(10종)
→ 학습/정확도 평가/그래프 PNG 저장
```

## 5. 핵심 수식과 기호

이미지 패치 개수: $P=(H/p)\times(W/p)$. 여기서 **H**는 이미지 높이, **W**는 너비, **p**는 한 패치의 한 변 크기, **P**는 전체 패치 개수입니다.

어텐션: $\operatorname{Attention}(Q,K,V)=\operatorname{softmax}(QK^T/\sqrt{d_k})V$. **Q**는 찾고 싶은 정보(Query), **K**는 비교할 단서(Key), **V**는 실제 전달할 정보(Value), **d_k**는 Key 벡터의 차원입니다. 여러 헤드가 서로 다른 관계를 병렬 학습합니다.

이 소스에서는 $P=(32/4)^2=64$개 패치이며, 각 패치의 원본 값은 $4\times4\times3=48$개이고 투영 후 차원은 64입니다.

## 6. 실제 코드 단계별 해설

**① 데이터:** `keras.datasets.cifar10.load_data()`는 10개 분류 문제의 훈련·시험 영상을 불러옵니다.

**② 패치 추출:** `tf.image.extract_patches(..., sizes=[1,4,4,1], strides=[1,4,4,1])`는 겹치지 않는 4×4 패치를 얻습니다. `reshape` 후 `(배치, 64, 48)`입니다.

**③ 패치 인코딩:** `Dense(64)`가 패치 표현을 만들고 `Embedding(64,64)`가 위치를 보완합니다.

**④ 인코더:** `MultiHeadAttention(num_heads=8, key_dim=8)` 및 `LayerNormalization`, `Add`, GELU MLP로 표현을 갱신합니다.

**⑤ 분류/훈련:** `Flatten → Dense(2048) → Dense(1024) → Dense(10, softmax)`, `Adam`, 100 epochs, 배치 128입니다. **현재 들여쓰기로는 1개 블록만 생성되므로 수정이 필요합니다.**

**⑥ 결과:** `accuracy_graph.png`, `loss_graph.png`를 현재 작업 디렉터리에 저장합니다.

## 8. 코드 검토 및 오류 해결(원인 → 확인 → 수정)

- **원인 ① — 모델 생성 코드의 들여쓰기:** 현재 `model=keras.Model(...)`과 `return model`이 `for _ in range(N):` **안에 있습니다.** 따라서 설정값 `N=6`과 달리 실제 인코더 블록은 **첫 번째 블록만 만들어진 뒤 함수가 종료**됩니다. **확인:** 해당 두 줄의 들여쓰기와 `model.summary()`의 MultiHeadAttention 개수를 비교하세요. **수정:** 두 줄을 반복문 **밖으로 한 단계 내리고**, 반복문 뒤에 분류 헤드를 둡니다.
- **원인 ② — 손실 함수와 출력의 불일치:** 출력층이 `softmax`인데 손실 함수가 `SparseCategoricalCrossentropy(from_logits=True)`입니다. **확인:** `Dense(n_class, activation='softmax')`. **수정:** `from_logits=False`로 변경하거나 기본 `SparseCategoricalCrossentropy()`를 사용합니다.
- **원인 ③ — 학습용 정규화 층:** `Normalization()` 층은 `adapt(x_train)`으로 통계값을 학습하며, `/255`와는 다릅니다. **확인:** `model.layers[1].adapt(x_train)` 및 입력 형식을 점검합니다.
- **최신 보충 내용:** `validation_data=(x_test, y_test)`는 학습 중 모델 선택용 검증에 테스트 데이터를 사용하는 방식입니다. 일반적인 성능 평가에서는 훈련/검증/최종 테스트를 분리하세요. 학습 전에 `epochs=1`로 동작 점검을 권장합니다.

## 9. 확인 문제 3개 — 정답 대신 힌트

1. **32×32 이미지를 4×4 패치로 나누면 몇 개인가요?** 힌트: 세로 8개 × 가로 8개.
2. **위치 임베딩이 없으면 무엇이 어려워질까요?** 힌트: 퍼즐 조각의 원래 자리.
3. **`N=6`인데 인코더가 한 개만 생성되는 까닭은?** 힌트: `return model`의 들여쓰기.

## 10. 미니 과제

`epochs=1`로 먼저 실행한 뒤 반복문 안의 `return`을 밖으로 옮기고 `model.summary()`에서 인코더 블록 수를 비교하세요. 변경 전후 실행 시간을 기록하되 정확도 개선을 보장하지는 않습니다.

## 11. 오늘의 핵심 요약

ViT는 영상 패치와 위치 정보를 입력으로 사용하고, 주목 기법으로 패치 사이 관계를 학습합니다. 현재 첨부된 코드는 **반복문 내부 반환** 및 **softmax-손실 설정**을 점검해야 합니다.
