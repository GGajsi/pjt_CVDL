# 11-4 — DETR 기반 이미지 물체 검출 — 교재형 원본 코드

3. 11-4_1 수정본에서 무엇이 해결되는지 이해한다.

## 3. 핵심 개념 — 일상 비유

YOLO가 사진을 보면서 물체를 찾는 탐정이라면, DETR은 여러 **질의 카드(object queries)**를 이용해 사진에서 물체 후보를 동시에 조사하는 팀과 비슷합니다.

## 4. 프로그램 처리 흐름

```text
BSDS_361010.jpg → DetrFeatureExtractor
→ facebook/detr-resnet-50 → logits + pred_boxes
→ 클래스 선택 → 박스 좌표 계산 → OpenCV 사각형/라벨
```

## 5. 핵심 수식과 기호

예측 상자 `(c_x,c_y,w,h)`를 `(x_1,y_1,x_2,y_2)`로 바꾸는 식: $x_1=(c_x-w/2)W$, $x_2=(c_x+w/2)W$, $y_1=(c_y-h/2)H$, $y_2=(c_y+h/2)H$. **cₓ,cᵧ**는 정규화 중심 좌표, **w,h**는 정규화 너비·높이, **W,H**는 **실제 입력 이미지** 너비·높이입니다.

## 6. 실제 코드 단계별 해설

**① 모델:** `DetrFeatureExtractor` 및 `DetrForObjectDetection`으로 `facebook/detr-resnet-50`을 불러옵니다.

**② 점수:** `res.logits[0,i]`에서 클래스별 점수를 다룹니다. 소스에서는 `predicted_label!=91` 조건으로 특정 분류 번호를 제외합니다.

**③ 박스:** `res.pred_boxes`에서 정규화 중심 좌표를 얻고 코드에 고정된 `481`, `321`을 곱합니다.

**④ 시각화:** OpenCV로 사각형과 클래스 이름을 표시합니다. 하지만 확률 계산과 좌표 처리는 수정이 필요합니다.

## 7. 실행 준비와 방법

필요: `torch transformers pillow numpy opencv-python`, `BSDS_361010.jpg`, 모델 다운로드 인터넷 연결. 원본의 오래된 `DetrFeatureExtractor`는 경고가 나타날 수 있습니다.

## 8. 코드 검토 및 오류 해결(원인 → 확인 → 수정)

- **원인 ① — 잘못된 확률 축:** `res.logits[0,i].softmax(dim=0)`은 **클래스 점수 벡터에 대해서는** 실제로 적절한 축입니다. 기존 코드의 문제는 **신뢰도 필터링을 하지 않고** `predicted_label != 91`만으로 표시한다는 점입니다. **확인:** 낮은 신뢰도 객체 박스가 많은지. **수정:** 클래스별 점수에서 배경(no-object)을 제외하고 임계값 필터를 사용하세요. `11-4_1`은 후처리 함수를 사용합니다.
- **원인 ② — 이미지 크기 하드코딩:** `481`,`321`로 좌표를 변환. **확인:** `img.size`. **수정:** 실제 이미지 크기로 좌표를 계산하거나 모델의 `post_process_object_detection`를 사용합니다.
- **원인 ③ — 색상 인덱스:** `colors[predicted_label]`은 100개만 준비해 둡니다. **확인:** 클래스 인덱스가 100 이상이면 IndexError. **수정:** `% len(colors)`를 사용합니다.
- **최신 보충 내용:** 수정본 `11-4_1.py`를 실습용 우선 버전으로 권장합니다.

## 9. 확인 문제 3개 — 정답 대신 힌트

1. **DETR에서 box 네 값은 어떤 좌표 형식일까요?** 힌트: 중심과 너비/높이.
2. **사진 크기를 숫자로 고정하면 무엇이 문제인가요?** 힌트: 다른 사진으로 바꿔 보기.
3. **배경(no-object) 클래스가 필요한 이유는?** 힌트: 모든 query가 물체를 찾는 것은 아닙니다.
